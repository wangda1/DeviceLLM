# T-008 S4 融合规则与调参
**环境**: 🐧 Linux · **依赖**: T-005, T-006, T-007 · **规模**: M · **里程碑**: M1

## 背景
把 S1 + S2 + S3 的特征转成分数和标签，见 SPEC §4 S4。规则必须可以解释（`evidence` 字段），并且由 C++ 核心直接执行同一份规则文件。

## 交付物
- `assets/rules.yaml`：规则以**数据**的形式定义（阈值、权重、场景修正）；构建时生成 `rules.json` 供核心读取
- 规则表达式只允许一个很小的 DSL（比较、与或、加权求和、分段线性映射），并写清楚它的语法，C++ 端照着实现解释器
- `ml/photocritic/fusion.py`：规则解释器（Python 版）
- 维度分数的计算公式（各特征加权后映射到 0–100）
- `intentional_possible` 的判断逻辑（场景标签加上特定的特征组合，例如剪影：主体全黑但边缘很清楚）
- 调参脚本：在 synthetic dev 集上网格搜索或贝叶斯优化阈值，以宏平均 F1 为目标，结果写回 `rules.yaml`
- `suggested_crop` 的生成：根据显著性 bbox 往三分线对齐，并保持原图比例

## 验收标准
- [ ] `rules_only` pipeline（S1 + S2 + S3 + S4）在 synthetic test 集上给出基线宏平均 F1
- [ ] 每个标签的 `evidence` 都能指出是哪条规则、哪个特征触发了它
- [ ] 规则文件只使用 DSL 中定义的语法
